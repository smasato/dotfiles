# UI/UX verification

## 1. 確認対象を絞る

依頼と既存資料から次を特定する。

- 対象画面と、ユーザーが達成したいこと
- 確認対象の URL・実装版または試作
- 利用者の権限、初期データ、開始状態
- 対象の画面サイズと入力方法

調べられる事実は自分で確認する。
未決の利用条件が判断を変える場合だけ、ユーザーに質問する。

今回は何を確認し、何を対象外にするかを決めてから進む。
試作・モックと、実際のバックエンドを使う画面を区別する。

## 2. 観察環境を用意する

ブラウザ操作には agent-browser スキルを読み、
その手順で専用セッションを使う。

テスト環境とテストデータを優先する。
送信・購入・削除など実データに影響する操作は、
依頼で許可された範囲内だけ実行する。
画像やログへの個人情報・認証情報の混入を避ける。

画像を撮影できることと、モデルが画像を閲覧できることを
別々に確認する。閲覧できなければ視覚評価は未検証とする。

## 3. 見た目と構造を照合する

対象状態ごとに、同じ画面の次の情報を確認する。

- スクリーンショットによる配置・余白・文字・重なり
- DOM またはアクセシビリティツリーによる名前・役割・状態

スクリーンショットは実際の表示領域を基本とし、
必要に応じて全体画像や部分拡大を追加する。
比較時は画面サイズ・ズーム・テーマ・データを揃える。

画面構造は操作対象の特定に使い、見た目の根拠には画像を使う。
寸法やコントラストの数値が判断に必要なら測定する。

仕様検討では、改善案の前に現在の画面と操作の理解を短く示す。
理解が未確認の箇所は明記する。

## 4. 利用シナリオを実行する

各シナリオを次の順で確認する。

開始状態 → 操作 → 観測結果 → 期待結果との比較

各操作後は、期待する表示や状態変化を待って情報を取り直す。
操作コマンドの成功ではなく、ユーザーの目的達成を確認する。

依頼に関係する状態を選んで試す。

- 通常の成功経路
- 空状態、入力エラー、通信失敗
- 読み込み中、無効状態、重複操作
- キャンセル、戻る、再試行
- キーボード操作とフォーカス
- 対象端末での表示と操作

未実行の状態は、理由とともに未検証として残す。
確認対象を無断で全画面・全端末の監査へ広げない。

## 5. 動きと使いやすさを評価する

時間に関する主張には、録画・時刻付き連続画像・計測を使う。
静止画だけでアニメーションや応答速度を評価しない。
録画を直接閲覧できなければ、必要なフレームを抽出する。

「操作が見つけにくい」「迷いそう」は UX 上の仮説として示し、
観察した配置・文言・操作手順を根拠に添える。
実ユーザーの行動を観察していない限り、
ユーザーテスト済みとは扱わない。

仕様上の選択が必要なら、観察結果と選択肢を
進行中の仕様議論へ返す。grilling を使っている場合は、
その質問ラウンドに戻し、合意前に仕様を確定しない。

## 6. 根拠を添えて報告する

報告には次を含める。

- 確認した環境とシナリオ
- 観察事実と、参照できる画像・ログ
- 推測や UX 上の懸念
- 改善案と、ユーザーの判断が必要な点
- 未検証の状態と理由

指摘ごとに再現手順・実際の結果・期待結果を対応づける。
ローカル成果物はローカルパスとして示し、
共有可能なリンクと区別する。

対象シナリオが検証済み、または理由付き未検証として
整理され、各指摘に根拠があれば完了とする。
このスキルだけでは実装変更や Issue 登録を開始しない。
